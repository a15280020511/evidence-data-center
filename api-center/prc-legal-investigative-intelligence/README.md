# 中国大陆法律、司法与电子证据联合情报目录

## 目标

为情报中心提供一个不重复建设爬虫的中国大陆法律、司法实践与公开侦查知识入口。模块把元典的法条/案例召回能力，与全国立法、法院、检察、公安程序、司法行政、行政复议/执法监督、执行破产、专项审判、纪检监察、司法鉴定、法官/检察官/公安/监察培训以及地方司法官方来源族组合起来。

本模块仅用于防御性合规、法律风险识别、司法实践研究、证据完整性与审计准备。不得用于隐藏身份、规避依法调查、删除证据、反取证、绕过验证码/WAF/403/429、代理/IP轮换、隐藏接口扫描、私有接口逆向或获取秘密侦查技术。

## 四张矩阵

### 1. `legal-system-matrix.json`：中国大陆法律体系矩阵

回答“这个问题属于哪条司法/法治主线，应查哪些官方来源”。覆盖国家立法法源、法院、检察、公安侦查程序、司法行政、行政复议/执法监督、执行破产、专项审判、监察职务犯罪衔接及省市县地方司法来源族。

全国性平台包括国家法律法规数据库、全国人大、国务院公报、司法部法规规章、最高法及公报、人民法院案例库、中国裁判文书网、审判流程、庭审公开、执行信息、人民法院公告、企业破产重整、减刑假释暂予监外执行、最高法知识产权法庭、最高检、12309、公安公开程序规则、12348、司法行政案例库、全国行政复议服务平台等。

实名当事人服务与公开情报严格分开：12309案件查询、审判流程个案查询、在线复议申请等只登记能力，不由情报中心自动登录或提交。

### 2. `investigative-evidence-matrix.json`：法律依据与证据/侦查类别矩阵

回答“依法可能涉及哪些证据、程序、完整性和调查类别”。只保存公开法定类别和程序边界，不保存技术侦查秘密实现或规避方法。

### 3. `source-catalog.json`：基础法律与专项监管目录

保存元典、网信、市场监管、TC260、保密、自然资源、工信等基础与专项监管来源。

### 4. `public-security-knowledge-practice-matrix.json`：司法知识与实践双视角矩阵

虽然沿用历史文件名，但当前 v2 已扩展为全国司法/公安/检察/纪检监察知识与实践矩阵。

它采用两种互相校验的视角：

```text
源头视角 SOURCE
公开法条/程序
+ 公安、法官、检察官、司法警官、监察培训
+ 公安/司法/检察技术标准
+ 公安院校/纪检监察学院培养方案
+ 司法鉴定科研和专业期刊
+ 官方业务新闻与研究
        ↓
抽象出公开声明的能力域、证据逻辑和业务体系

结果视角 OUTCOME
元典大规模案例召回
+ 法院案例/裁判文书
+ 最高检技术案例/典型案例
+ 公安公开案件通报
+ 纪委监委公开审查调查/案件审理实践
+ 司法鉴定公开实践
        ↓
提取现实案件中公开出现的证据组合、程序问题和结果

SOURCE × OUTCOME
        ↓
现行法律和官方一手材料复核
        ↓
形成高置信司法实践判断
```

## 为什么“课程”不能等同于自动抓课件

课程体系很适合判断一个机关公开培养什么能力，但必须区分公开元数据和内部学习内容。

允许自动进入矩阵的内容：课程名称、专业培养方案、公开教学大纲、公开培训通知、官方课程分类、公开教材目录/摘要、科研项目和公开论文元数据。

不自动获取：需要账号的法官培训网课件、检察教育培训网络学院内部课程、公安在职内部培训、纪检监察非公开课程、任何密级或内部资料。

## 从公开案例了解侦查/调查能力

可以，但只做“案例衍生实践分析”。矩阵允许提取：

- 案件来源、时间和程序阶段；
- 公开披露的线索来源；
- 公开披露的证据种类；
- 证据之间如何相互印证；
- 身份/账号/网络/终端等归因因素；
- 电子数据、法医、物证、声像、司法会计等技术性证据审查类型；
- 公开披露的平台、运营商、银行或其他机构依法协助；
- 公开披露的跨机关协作；
- 证据合法性、真实性、关联性或证明力问题；
- 检察监督、起诉、监察处理或法院裁判结果；
- 案例能够证明的高层能力域及置信度。

禁止提取：秘密系统名称、秘密工具、监控参数、隐蔽采集配置、目标选择规则、侦查盲点、规避/反取证方法、私有接口、非公开培训资料和战术操作手册。

因此系统能够回答的是：

> “从公开制度、课程和标准看，相关机关公开建设了哪些能力；从公开案例看，这些能力在现实案件中体现为哪些证据组合和程序。”

不能回答的是：

> “内部秘密系统具体怎么部署、怎样避开这些系统、哪些检测阈值和盲区可以利用。”

## 元典与官方来源职责分工

```text
具体法律/司法问题
→ 元典：法条、案例大范围召回和同义词扩展
→ legal-system-matrix：确定司法体系主线
→ public-security-knowledge-practice-matrix：SOURCE/OUTCOME 双视角补强
→ 国家法律法规数据库/全国人大/国务院/司法部：现行法和效力
→ 法院/检察/公安/监察/司法行政官方材料：案例、程序、培训和实践复核
→ investigative-evidence-matrix：证据类别、完整性、归因和法定程序
→ 行业监管/专项红线
→ 平台授权、合同和数据权利复核
→ GREEN / YELLOW / ORANGE / RED / REVIEW_BEFORE_PRODUCTION
```

元典是召回层，不是最终法律权威。培训材料、新闻和学术论文也不是最终法律依据；重要结论必须回到当前有效的官方法条、司法解释、正式规则和一手案例。

## 重点公开能力域

当前矩阵抽象到高层的能力域包括：受案立案与管辖协作、侦查组织和证据推理、现场物证、电子数据、网络犯罪、身份/账号/网络/终端关联、资金交易、通信内容、视频图像音频、法医生物、毒化理化痕迹文件、数据情报跨源关联、地理遥感与现场技术证据、平台/运营商/机构记录、讯问询问与言词证据、检察技术性证据审查、法院证据审查、纪检监察监督检查/审查调查/案件审理、司法鉴定质量控制和技术侦查公开法定边界。

## 接入规则

优先级：

```text
官方文档化 API
> RSS / Atom / Sitemap / 官方批量下载
> HTML / PDF / XLSX / CSV / JSON / XML
> 官方公开检索数据库的有界查询
> 现有受控 web-retrieval
> 人工或明确授权导出
```

禁止自动登录、验证码破解、WAF绕过、拒绝后换IP/账号/Key/Provider、隐藏API逆向、无限分页、个人画像、反取证和侦查规避。

对于裁判文书网、人民法院案例库、执行信息网等检索型系统，只做有界查询、增量检索和缓存；遇登录、验证码、403、429或平台拒绝即停止。地方来源必须经中央机关/政府官方链接或当前官方域名验证。

## 操作

- `catalog-capabilities`：读取能力目录和矩阵摘要；
- `source-catalog`：筛选基础/专项来源；
- `source-route`：读取基础来源路由；
- `legal-system-matrix`：读取全国法律体系、法源家族和官方平台；
- `investigative-evidence-matrix`：读取法定证据/侦查类别；
- `public-security-practice-matrix`：历史操作名，当前用于读取 v2 全国司法知识与实践双视角矩阵；
- `joint-audit-plan`：生成元典＋法律体系＋公开知识/案例实践＋官方法源＋证据程序＋监管红线的联合审计顺序。

## 非公开边界

本矩阵追求的是“中国大陆公开司法体系高覆盖”，而不是非法获取内部司法网络。公安内部数据库、秘密技术侦查方法、法院/检察内部专网、纪检监察非公开审查调查材料、密级培训课件、密封/隐私案件和实名当事人后台不属于自动情报采集范围。
