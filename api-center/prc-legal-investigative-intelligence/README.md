# 中国大陆法律、司法与电子证据联合情报目录

## 目标

为情报中心提供一个不重复建设爬虫的中国大陆法律合规审计入口。该目录把元典的法条/案例召回能力，与全国人大、最高法、最高检、公安刑事/行政程序、公安电子数据规则、网信、市场监管、TC260、保密、自然资源、工信等公开官方来源组合起来。

本模块仅用于防御性合规、法律风险识别、证据完整性与审计准备。不得用于隐藏身份、规避依法调查、删除证据、反取证、绕过验证码/WAF/403/429、代理/IP轮换、隐藏接口扫描或私有接口逆向。

## 当前法律基线

法律结论必须先经元典广泛召回，再以当前官方来源核验有效性。2026-08 的重点基线包括：

- 《中华人民共和国刑事诉讼法》现行文本；
- 《公安机关办理刑事案件程序规定》（2020修正，使用前继续核验是否有后续修改）；
- 《关于办理刑事案件收集提取和审查判断电子数据若干问题的规定》；
- 《中华人民共和国网络安全法》2025修正文本，自2026-01-01施行；
- 《中华人民共和国数据安全法》；
- 《中华人民共和国个人信息保护法》；
- 《网络数据安全管理条例》，自2025-01-01施行；
- 《中华人民共和国反电信网络诈骗法》；
- 《公安机关办理行政案件程序规定》（2018修正，使用前继续核验是否有后续修改）；
- 《中华人民共和国治安管理处罚法》2025修订文本，自2026-01-01施行；
- 《中华人民共和国反不正当竞争法》2025修订文本；
- 《中华人民共和国保守国家秘密法》2024修订文本及现行实施条例。

`investigative-evidence-matrix.json` 负责保存这些现行法律层、程序层和证据类别，避免把“法律依据”和“来源网站”混成一张表。

## 为什么不为每个官网重复写爬虫

现有 `web-retrieval` 已经提供受控的公开网页/PDF读取、搜索、提取和有限站点映射能力。新模块只负责：

1. 固定官方来源清单；
2. 权威等级；
3. 接入等级；
4. 元典与官方复核的顺序；
5. 现行法律/程序/证据类别矩阵；
6. 选择现有 Provider 路由；
7. 在出现登录、验证码、WAF、403/429等信号时保持 fail-closed。

## 联合审计顺序

```text
具体工具/账号/行为/数据/用途
→ 情报中心 PRC 风险门
→ 元典：法条 + 案例广泛召回
→ 国家法律法规数据库：确认现行有效文本、公布/施行日期和历史沿革
→ 刑事诉讼法 / 治安管理处罚法 + 公安刑事/行政办案程序：确认法定权限和程序
→ 两高一部电子数据规定：确认电子数据范围、提取、冻结、完整性、真实性/合法性/关联性
→ 人民法院案例库 + 最高法 + 最高检：类案、证据与司法实务
→ 网络安全法 / 数据安全法 / 个保法 / 网络数据安全条例 / 反电诈法：平台、运营商、金融机构、数据处理者义务和法定协助边界
→ 网信 / 市场监管 / 工信 / 国家数据局 / 知识产权：行政与行业监管
→ 证据与归因矩阵：身份账号、日志、通信、交易、设备、在线数据、依法调取、查询冻结、证据保全等类别
→ TC260 / CNCERT：技术合规与安全风险
→ 国家保密局 / 自然资源部：国家秘密与测绘地理独立红线
→ GREEN / YELLOW / ORANGE / RED / REVIEW_BEFORE_PRODUCTION
```

元典是召回层，不是最终法律权威。最终结论必须结合当前有效的官方法条、司法材料、监管材料和具体平台授权条款。

## 防御性证据/侦查类别

模块只描述法律上公开可知的类别和程序边界，不描述技术侦查的具体实现能力、部署方式、识别弱点或规避方法。当前矩阵包括：

- 身份、账号与现实主体关联；
- 登录、访问、通信、域名解析、云服务和应用审计日志；
- 短信、邮件、即时通信、公开网页、云文件等通信与内容电子数据；
- 银行、支付、商户和交易记录；
- 手机、计算机、磁盘等设备与原始存储介质；
- 网络在线提取、远程电子数据和云端记录；
- 依法调取以及平台/运营商依法提供技术支持和协助；
- 勘验检查、搜查、查封扣押、证据保全；
- 查询、冻结与数据保全；
- 鉴定、辨认和专门性审查；
- 技术侦查的法定适用、严格审批、范围、期限和用途限制；
- 网络数据行政监管检查；
- IP、网络活动、终端、账号、交易、内容等多来源同一性/关联性判断；
- Hash、备份、封存、录像、访问日志、数字签名/证书、来源时间等完整性和证据链；
- 国家秘密、商业秘密、个人隐私/个人信息的保密、范围和用途限制。

这些类别用于回答“某种行为会留下哪些依法可验证的记录、什么情况下需要提高合规等级、证据是否具备完整性”，不能用于回答“怎样不被发现、怎样清除痕迹、怎样规避技术侦查”。

## 接入规则

优先级：

```text
官方文档化 API
> RSS / Atom / Sitemap / 官方批量下载
> HTML / PDF / XLSX / CSV / JSON / XML
> 官方公开检索数据库的有界查询
> 现有受控 web-retrieval
> 人工或明确授权导出
```

禁止：自动登录、验证码破解、WAF绕过、拒绝后换IP/账号/Key/Provider、隐藏API逆向、无限分页、个人画像、反取证和侦查规避。

## 操作

- `catalog-capabilities`：读取本地能力目录和法律矩阵摘要。
- `source-catalog`：按主题、访问类别或证据权重筛选来源。
- `source-route`：获取某固定来源应复用的现有 Provider 路由。
- `investigative-evidence-matrix`：读取/筛选现行法律层与防御性证据/侦查类别。
- `joint-audit-plan`：按风险主题生成元典 + 官方法条 + 程序 + 电子证据 + 监管 + 红线 + 证据类别映射的联合审计顺序。

## 典型使用

普通公开法条核验：国家法律法规数据库优先；元典用于发现相似法条和案例。

数据采集/爬虫/自动化争议：元典 + 现行数据/网络/反不正当竞争法律 + 最高法/最高检案例 + 市场监管典型执法 + 平台条款。

公安电子数据问题：刑事诉讼法 + 公安刑事程序 + 两高一部电子数据规定；只用于理解依法取证范围、程序、完整性和证据审查，不输出规避建议。

实名账号/平台日志问题：个保法国家机关处理规则 + 数据安全法依法调取 + 现行网络安全法技术支持协助义务 + 平台自身公开条款。

电信网络诈骗相关风险：反电诈法的实名、日志、平台协助、异常账户/交易和资金查询冻结机制作为专项层。

数据出境/个人信息：网信办现行法规与政策问答 + TC260技术指南。

高精度地理/测绘：自然资源部专项门。

涉密迹象：国家保密局专项门并直接升级审查。
