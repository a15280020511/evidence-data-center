# BaoStock 生产配额与黑名单控制

生产环境执行以下硬约束：

- 统计时区：`Asia/Shanghai`
- 每日上游查询最多：`50,000`
- 最大并发连接数：`1`
- GitHub Actions 全局并发组：`api-baostock-global-single-connection`
- 每个非本地票据在登录 BaoStock 前预占 1 次请求
- 第 50,000 次预占允许执行，但立即激活当天本地黑名单
- 当天后续请求在 `login()` 和查询函数之前拒绝
- 下一上海自然日自动清零计数并解除本地黑名单
- 配额台账不可读取、不可解析或不可更新时，执行失败关闭，禁止访问 BaoStock
- 本地 `catalog-capabilities` 不访问上游，不消耗配额

配额状态保存在仓库系统 Issue `#297` 的固定机器管理评论中。由于工作流采用仓库级全局串行并发组，读取、递增和回写不会由两个 BaoStock 任务同时执行。

预占发生在上游调用之前。即使后续网络失败、查询失败或工作流被取消，该次预占也不会退回，因为请求尝试已经占用风险预算。该设计优先避免超过 50,000 次和触发上游黑名单。
